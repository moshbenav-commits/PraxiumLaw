# Practice-Area Module Template

Every module spec fills in exactly these sections. A module is **configuration + content on the shared core** ([README](./README.md)) — if a section needs new *platform* capability, that capability is built in the core and flagged `CORE-BUILD`.

## Sections

1. **Scope** — what case types are in/out; auto-refer-out triggers.
2. **Intake deltas** — additional questions, disqualifiers, urgency triggers (evidence about to disappear, imminent deadline categories), required day-one evidence.
3. **Lifecycle deltas** — phases added/changed vs. the [PI lifecycle](../pi-case-os/articles/00-case-lifecycle-and-workflow-map.md); new attorney gates.
4. **Document pack** — module-specific templates (white-label, counsel-certified per jurisdiction).
5. **Deadline pack** — the vertical's killer-date *categories* (numbers live in the [Jurisdiction Matrix](../pi-case-os/JURISDICTION_MATRIX.md), verified by counsel).
6. **Damages model deltas** — what the [damages worksheet](../pi-case-os/DAMAGES_WORKSHEET.md) adds/removes.
7. **Counterparty map** — who's across the table (carrier types, TPAs, agencies, defense bar patterns) and what negotiation rail applies.
8. **Compliance flags** — vertical-specific ethics/regulatory landmines.
9. **KPIs** — module-specific additions to the [core KPI set](../pi-case-os/KPIS_AND_CASE_GRADE.md).
10. **Reuse map** — which core components are used unchanged (should be most of them).
